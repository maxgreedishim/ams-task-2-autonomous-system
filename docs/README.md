# AMS Task 2 — документация

Документация рабочего прототипа направления B «Управляемые действия».

## Source of truth

Базовый источник требований:

`/Users/max/Downloads/AMS_задание_2_автономная_система.pdf`

При расхождении документации проекта, кода и задания сначала фиксируется расхождение, а требования
PDF считаются нормативными для проверки. README и docs описывают только фактически реализованную
часть и явно отмечают ограничения.

## Принципы

- документация живёт рядом с кодом и описывает фактическое поведение;
- требования трассируются к API, событиям и автоматическим тестам;
- mock-система изолирована от реальных CRM и персональных данных;
- изменения архитектуры фиксируются в `adr/`.

## Структура

- `00-vision` — цель и ценность;
- `01-glossary` — термины;
- `02-context` — границы системы;
- `03-scope` — включённый и исключённый scope;
- `04-usm` — пользовательские сценарии;
- `05-requirements` — требования направления B;
- `06-api` — HTTP-контракт;
- `07-events` — audit-события;
- `08-data` — SQLite-модель;
- `09-nfr` — безопасность и эксплуатационные требования;
- `10-acceptance-tests` — трассируемость требований к тестам;
- `adr` — архитектурные решения.

## Форматирование

- все документы пишутся в Markdown;
- обычный текст переносится примерно на 100 символах;
- таблицы и fenced code blocks сохраняют формат Markdown;
- длинные однострочные абзацы не используются.
